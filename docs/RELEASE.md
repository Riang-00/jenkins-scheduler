# Release 2.1.1

新增 Git Parameter 插件支持：读取 Jenkins 的分支或标签选项，预约保存所选值；执行前重新验证，选项失效或列表读取失败时停止执行。支持刷新参数，默认分支仅在明确匹配时预选。配置与预约数据格式保持兼容。

## 2.1.0

首个可独立分发的 Windows x64 安装版：多 Jenkins、多账号、项目分类和参数化预约，内置 Python 3.13.17。

## 安装与升级

下载 GitHub Release 中的安装器，在当前 Windows 用户下安装。安装完成不会自动打开应用。安装器将数据目录的绝对路径记录在 `install-location.json`，桌面和定时任务始终读取同一目录。

升级前关闭界面，取消尚未执行的预约或等待结束。升级只替换程序文件；普通复制失败会回滚程序。配置、加密账号、预约结果均不参与回滚。断电或磁盘损坏后若留下维护标记，请保留数据并重装完整程序，核对记录后再安排新的部署。不要恢复旧预约快照或手动重置状态。

卸载同样检查未完成或损坏的预约，只删除安装清单中的程序文件，保留用户数据。旧的内部开发版本不自动迁移；此安装版从空配置开始。

## 构建与发布

1. 执行 README 的 Python、前端和 native 检查。
2. 在隔离目录验证全新安装、升级保留数据、活动预约阻止升级/卸载、卸载保留数据。
3. 构建 `tools/build_release.py --exe <新构建的EXE> --revision <Git SHA>`。
4. 发布安装器与 `SHA256SUMS.txt`。只上传源码及明确允许的产物，禁止上传 `data/`、`.staging/`、日志、WebView 配置或任何个人账号。

推送 `v*` 标签会触发 Windows GitHub Actions，运行检查、构建并创建草稿 Release。检查安装包后将草稿发布。

安装器的 `/S` 为静默安装；`/DATA_DIR=<绝对路径>`、`/NO_SHORTCUTS` 及 NSIS 最后一个 `/D=<绝对路径>` 参数可用于隔离测试。正式升级必须保持原程序位置和原数据位置。
